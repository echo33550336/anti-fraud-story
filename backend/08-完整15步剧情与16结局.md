# 《终场前的两张票》完整15步设计

> 2026-10-30，完整设计稿。以本轮用户要求为准：一条主线、一名主角、若干配角含诈骗犯、15个正常节点、每步至少2选项、3个开放节点、2完美+14遗憾结局。人物、票务服务、资料、付款与授权均为虚构演练。尚未接入实际游戏或真实模型。
>
> 本稿细化并调整07的步骤，把资料、授权、资金三项补救分开，固定开放题为N12/N13/N14。旧稿仅供构思参考；实现应按本稿与配套09配置对齐。选项ID是内部标识，页面按配置中的ui_option_order排列，不给玩家显示“全选A”的提示。

## 一、故事底稿与固定真相

玩家扮演23岁的林夏。今天16:20有一场重要展示，今晚19:30有一场一直想看的演出。旧同学小岚送来两张票，想在结束后说清自己的心意；两个冒充票务人员的诈骗角色利用同一事件提出异常操作。赠票真实、好意真实、冒充售后也真实，三件事分别核实。

小岚被直接询问时会诚实回答，不拖延核验来制造悬念。第12步揭晓完整情感，不是第一次允许玩家确认身份。阿舟只能帮助整理已知事实，平台工作人员只回复玩家实际提交的查询；模型不得临时编造决定性证据。

出场角色：林夏（唯一主角）、小岚（真诚的旧友与感情对象）、阿舟（可信朋友）、虚构平台工作人员、冒充“票务售后”和“审核专员”的两个诈骗角色。

固定节点顺序：N01→N02→…→N15。正常体验约5～8分钟，真实时长待试玩。随时可以停止演练，提前退出仅复盘已发生选择，不伪称走完15步。

## 二、逐步剧本

### N01｜一条不在计划里的提醒（第1幕，故事时间15:40）

**场景：** 展示还有四十分钟。你合上电脑，手机弹出来自陌生会话的赠票提醒，封面是你一直想看的演出。

> 系统：“[虚构赠票提醒]：今晚19:30，两席待确认。”

> 林夏：“两张？会是谁？”

**当前场景选项与即时回应：**

- 内部ID A：**先记下消息来源，把展示准备暂停一分钟**。回应：你把两件事分开处理，屏幕上的提醒不再像一道必须立刻回答的命令。
- 内部ID B：**边检查演示边回复，争取一起解决**。回应：文件和消息来回切换，你只记住了“今晚”和“两张票”。

**评分与状态：** 不因忙碌或反应速度扣安全分；影响节奏和后续旁白。

**下一步：** N02。

### N02｜熟悉的人，陌生的入口（第1幕，故事时间15:42）

**场景：** 旧同学小岚发来消息。你们最近重新联系，过去一起做过一个没能完成的项目。

> 小岚：“晚上有件事想当面告诉你。你先准备展示，不用急着回。”

> 林夏：“赠票上的署名，很像我们当年的项目名。”

**当前场景选项与即时回应：**

- 内部ID B：**先把熟悉署名当作线索，等展示后再确认**。回应：你暂时没有下结论，把“赠票人是谁”放进了待确认列表。
- 内部ID A：**从原先保存的联系入口确认是不是小岚送的**。回应：小岚答：票是我送的。你可以自己查赠票记录，不用从陌生提醒进去。

**评分与状态：** 小岚的身份与票务来电分开。B不直接扣分；身份稍后仍可核实。

**下一步：** N03。

### N03｜自称售后的来电（第1幕，故事时间15:44）

**场景：** 陌生联系人说赠票订单有异常。它知道演出名称，但没有证明自己有权处理订单。

> 票务售后：“这笔赠票需要额外核对，请到[模拟处理页]继续。”

> 林夏：“它说的订单，和刚才那份礼物像是同一件事。”

**当前场景选项与即时回应：**

- 内部ID B：**先听说明，把操作决定留到核验之后**。回应：你仍留在会话里。听说明不等于已经核验，下一步仍由你决定。
- 内部ID A：**暂停回复，关闭可疑入口，自己查询**。回应：你结束了这次联系。后续相关请求只会以已拦截摘要出现。

**评分与状态：** 是否发生后续暴露取决于联系状态和实际选项；留在会话不自动写成损失。

**下一步：** N04。

### N04｜把两个问题分开查（第2幕，故事时间15:46）

**场景：** 你要查的是两件事：赠票有没有、陌生来电有没有处理权限。查询选择现已登记，结果在第11步固定返回。

> 林夏：“票是真的，也不代表这个来电是真的。”

**当前场景选项与即时回应：**

- 内部ID B：**只从官方入口查赠票有没有**。回应：你查了礼物是否存在，还没有查来电者是谁。
- 内部ID C：**先看对方发来的票面或证明，不自行查询**。回应：图片看起来完整，但目前仍是对方提供的材料。
- 内部ID A：**自己打开虚构官方入口，分别查赠票和来电权限**。回应：两个问题都已提交核验，等待答复。

**评分与状态：** 来源维度最终对应A=2、B=1、C=0。N02核实赠票人不能代替这一项核验。

**下一步：** N05。

### N05｜资料页面（第2幕，故事时间15:48）

**场景：** 活跃会话展示一张只含占位符的模拟资料卡，没有真实输入框。

> 林夏：“我还没确认这个入口，没必要现在交出整份资料。”

**当前场景选项与即时回应：**

- 内部ID B：**模拟提交整份资料，希望尽快完成**。回应：游戏记录了一次模拟资料暴露；之后删除聊天不能撤回这次事实。
- 内部ID A：**不向这个入口提交资料，保留请求待核实**。回应：资料没有离开模拟的个人保管区。

**条件文案：** 你此前已经结束可疑联系。现在显示的是已拦截资料请求摘要。

- 内部ID B：**保留拦截状态，继续查询订单**。回应：你没有重新开放入口，也没有提交资料。
- 内部ID A：**查看为什么这份资料请求值得警惕**。回应：你查看了请求范围和用途。

**评分与状态：** 只有仍处于可疑会话且选B才记模拟暴露。早断联者不能被后台安排泄露。

**下一步：** N06。

### N06｜换了一个人接话（第2幕，故事时间15:50）

**场景：** 对方把会话转给“审核专员”，出现模拟共享屏幕或账号授权请求。

> 审核专员：“后续由我核对。请查看[模拟授权请求]。”

> 林夏：“换了名字，来电权限的问题仍没解决。”

**当前场景选项与即时回应：**

- 内部ID A：**拒绝可疑授权，等待独立核验**。回应：你保留了对账户和设备的控制。
- 内部ID B：**选择模拟授权，继续看会发生什么**。回应：游戏记录了模拟授权暴露，设备没有执行真实共享。

**条件文案：** 你已结束可疑联系，审核专员的请求只出现在拦截摘要里。

- 内部ID A：**查看这类授权会涉及哪些信息**。回应：你读完授权范围提示，未授予权限。
- 内部ID B：**保持拒绝，不查看这份请求**。回应：拒绝仍有效，未发生授权。

**评分与状态：** 授权事件与资金事件分别记录。拒绝授权不自动终结所有剧情节点。

**下一步：** N07。

### N07｜退款为什么先付款（第3幕，故事时间15:52）

**场景：** 模拟处理卡上出现一项先付款的要求。演出时间和展示倒计时同时挤进你的注意力。

> 林夏：“我想把这件事赶快办完，但钱的方向好像不对。”

**当前场景选项与即时回应：**

- 内部ID B：**模拟继续付款，希望保住这份礼物**。回应：游戏记录模拟付款事件；没有连接真实支付，也不自动宣称资金可追回。
- 内部ID A：**拒绝异常付款，等待独立核验**。回应：没有发生模拟付款。你保留了再次判断的余地。

**条件文案：** 这项付款请求已经被拦截，只作为一张异常请求卡展示。

- 内部ID B：**保持拦截，继续处理自己的订单**。回应：没有付款，也没有重新接触对方。
- 内部ID A：**查看先付款要求与正常处理有什么冲突**。回应：你把异常请求记进核验清单。

**评分与状态：** 风险事件只来自实际模拟选择，不能凭后续总分编造损失金额。

**下一步：** N08。

### N08｜先把方向盘拿回来（第3幕，故事时间15:54）

**场景：** 阿舟看到你在几个页面间切换，递来一杯水。

> 阿舟：“先别急着证明自己没判断错。你已经做了哪些操作？我们一件件看。”

**当前场景选项与即时回应：**

- 内部ID C：**继续在原会话质问，想让对方给个说法**。回应：你想问清楚，但还在对方安排的沟通空间里。
- 内部ID A：**结束原可疑会话，不再跟随它的指令**。回应：你保留必要记录并停止回应；已发生的风险留到下一步处理。
- 内部ID B：**先停操作，但答应稍后回原会话继续**。回应：动作暂时停下了，原会话仍等着你回去。

**评分与状态：** 中止维度评价原冒充售后会话；正式求助渠道另由N12记录，避免重复归因。

**下一步：** N09。

### N09｜资料已经发出去了吗（第3幕，故事时间15:56）

**场景：** 显示你在N05的实际记录。已经暴露的资料无法靠一句“我现在知道了”消除。

> 阿舟：“先确认有没有发，再决定有没有需要补救的地方。”

**当前场景选项与即时回应：**

- 内部ID A：**按模拟资料暴露情况启动适用保护，限制继续扩散**。回应：你开始处理资料暴露；历史仍保留为曾经发生。
- 内部ID B：**暂不处理这次资料暴露，先把其他事办完**。回应：这项资料风险仍列在未完成事项里。

**条件文案：** 记录显示没有提交模拟敏感资料，这次无需补救资料暴露。

- 内部ID A：**核对一次记录，再继续**。回应：你确认没有资料提交事件。
- 内部ID B：**依据未提交记录直接继续**。回应：无需为不存在的暴露额外操作。

**评分与状态：** 未暴露=2；暴露且A=1；暴露且B=0。不强制无风险玩家采取补救。

**下一步：** N10。

### N10｜手机安静不等于权限安全（第4幕，故事时间15:58）

**场景：** 显示N06是否发生过模拟授权。若有，游戏提供一个抽象的权限处理确认卡。

> 林夏：“余额没变，只能说明暂时没看到资金变化。”

**当前场景选项与即时回应：**

- 内部ID B：**暂不处理授权，只看有没有异常消息**。回应：相关权限风险仍待处理。
- 内部ID A：**通过独立查到的适用入口处理模拟授权风险**。回应：授权风险已采取处理动作，历史暴露仍记录。

**条件文案：** 记录显示未授予可疑权限。

- 内部ID B：**依据未授权记录继续**。回应：未授权状态保持。
- 内部ID A：**查看权限记录确认一次**。回应：没有授权事件需要补救。

**评分与状态：** 未暴露=2；暴露且A=1；暴露且B=0。这里不处理资料、资金或证据评分。

**下一步：** N11。

### N11｜两份不同的答复（第4幕，故事时间16:00）

**场景：** N04选择的查询结果到达。同时显示N07是否发生过模拟付款。赠票记录和来电权限分开呈现。

> 林夏：“赠票是否存在、谁在联系我，是两个需要分别核实的问题。”

**只展示与先前选择相符的查询结果：**

- full：虚构官方入口分别回传赠票记录和来电权限核验结果。
- ticket_only：虚构官方入口仅确认赠票记录存在，来电权限仍未核实。
- provided_only：没有独立查询结果；目前仍是对方提供的票面图片。

**当前场景选项与即时回应：**

- 内部ID B：**暂不执行资金处理，等待退款自行到账**。回应：模拟资金事件仍未处理。
- 内部ID A：**按模拟资金事件执行适用的停止后续与风险处理动作**。回应：已采取模拟资金处理动作；结果仍需跟进，不承诺追回。

**条件文案：** 记录显示未发生模拟付款。展示与你选择的核验范围相符的结果。

- 内部ID B：**依据未付款记录继续**。回应：未付款状态保持。
- 内部ID A：**核对交易记录，确认没有模拟异常付款**。回应：没有付款事件需要止损。

**评分与状态：** 未暴露=2；暴露且A=1；暴露且B=0。N04未提交的查询不能凭旁白补成完成。

**下一步：** N12。

### N12｜真心与假售后（第4幕，故事时间16:03）

**场景：** 通过既有联络渠道联系到小岚。前段已确认其身份者听到进一步解释；尚未确认者现在获得剧情中的交叉确认。

> 小岚：“票是我送的，那个让你做额外操作的人不是我找的。你先把事情处理好，晚上的事可以以后再说。”

> 林夏：“我怕怀疑错了人，也怕因为喜欢就不敢问。”

> 小岚：“你愿意问清楚，我就认真回答。”

**本步问题：** 接下来，你准备向哪个渠道、怎样说明这次可疑联系？

**当前场景选项与即时回应：**

- 内部ID B：**找到正规入口，但只说一句“赠票出问题了”**。回应：渠道找对了，处理者仍不知道你是否提交资料、授权或付款。
- 内部ID A：**向独立查到的适用正规入口完整说明已做与未完成的事**。回应：你交代了时间、来源、实际操作及待处理问题。说明情况不会替你执行之前未做的补救。
- 内部ID C：**转向陌生消息里承诺快速解决的入口**。回应：你想尽快解决，却还没有独立核验这次求助入口。

**开放回答：** 增加“自己写”入口，预设选项始终保留。模型提取本步行动意图后，让玩家确认映射的操作；含义不明时不猜、不扣文采分。模型不能通过一句自述改写之前实际发生的行为。

**评分与状态：** 自写回答先映射A/B/C意图，含义不明请玩家确认。不因自称“我都处理了”改写历史事件。无资金/权限风险时，正规渠道可为平台核验与反馈，无须强加无关银行处置。

**下一步：** N13。

### N13｜给经历留下能用的线索（第5幕，故事时间16:06）

**场景：** 消息渐渐安静。你要决定怎样整理这次经过。

> 阿舟：“留下能说明事情的部分就好，别把自己的隐私到处转发。”

**本步问题：** 你会保留、整理哪些线索？

**当前场景选项与即时回应：**

- 内部ID C：**模拟清空必要记录，让这件事尽快过去**。回应：屏幕清静了，回看经过时却少了关键部分。
- 内部ID B：**只留一张最后的截图，不整理前后对应**。回应：你保留了部分材料，关键操作和时间还缺对应。
- 内部ID A：**整理必要来源、时间、操作和相关记录，遮蔽无关隐私**。回应：碎片被整理成可供核查的经过。

**开放回答：** 增加“自己写”入口，预设选项始终保留。模型提取本步行动意图后，让玩家确认映射的操作；含义不明时不猜、不扣文采分。模型不能通过一句自述改写之前实际发生的行为。

**评分与状态：** 不自动把“提供帮助”算成证据已齐全。C只改变剧情中的线索状态，演练选择日志仍用于复盘。

**下一步：** N14。

### N14｜你不欠我一次赴约（第5幕，故事时间16:10）

**场景：** 安全问题与后续事项已各自列明，小岚再次询问你的意愿。

> 小岚：“那两张票，是想认真约你一次。我喜欢你，你不用今天就回答。”

> 林夏：“如果我今天不来呢？”

> 小岚：“可以改天。如果你没有相同的心意，也可以直接告诉我。”

**本步问题：** 你想怎样回应这份邀请？

**当前场景选项与即时回应：**

- 内部ID A：**我愿意去，我们再确认公共入口和时间**。回应：小岚：好，按我们确认过的安排见。
- 内部ID B：**我想见你，但今天想先处理完事情，改天可以吗**。回应：小岚：可以，不急着今天。
- 内部ID C：**谢谢你准备这些，但我没有相同的心意**。回应：小岚：明白，谢谢你说清楚。

**开放回答：** 增加“自己写”入口，预设选项始终保留。模型提取本步行动意图后，让玩家确认映射的操作；含义不明时不猜、不扣文采分。模型不能通过一句自述改写之前实际发生的行为。

## 三、怎样从选择算出七个维度

| 维度 | 2级 | 1级 | 0级 | 对应步骤 |
|---|---|---|---|---|
| funds 资金 | 未模拟异常付款 | 发生过模拟付款，已采取资金处理 | 发生过模拟付款，未处理 | N07+N11 |
| authorization 授权 | 未模拟可疑授权 | 曾授权，已采取相关处理 | 曾授权，未处理 | N06+N10 |
| privacy 信息 | 未向可疑方提交资料 | 曾提交，已采取适用保护与限制扩散 | 曾提交，未处理 | N05+N09 |
| stop_contact 中止原会话 | 明确结束且不再跟随原会话 | 停止当前动作但约定稍后继续原会话 | 继续原会话 | N08 |
| official_help 正规求助 | 入口经独立核验，说明完整必要经过 | 正规入口正确，但必要经过不完整 | 跟随未核验的快速帮助入口 | N12 |
| source_verification 来源 | 完成票务记录与异常来电权限两项查询 | 只查赠票记录 | 仍依赖对方材料 | N04发起，N11按范围显示结果 |
| evidence 证据 | 线索按时间及操作对应整理 | 只保留局部材料 | 关键线索模拟删除或缺失 | N13 |

这些是本次演练完成度，不是人的人格、恋爱能力或实际被骗概率。主动求助不扣分；不存在暴露时，不强加补救任务。资料、授权、资金历史暴露一旦发生，补救后最多回到1，不能因爱情反转恢复到“从未发生”的2。

为避免重复归因，中止维度只评价原冒充售后会话，后续求助入口另记正规求助维度。N12只处理本步提交的说明与入口，不自动执行N09～N11尚未做的补救。N13只评必要线索，不自动宣布资金或权限风险已经解除。

**分数：** 资金/授权/信息/中止/求助/来源/证据权重依次21/19/17/15/13/11/9。原始分=96×Σ(权重×等级)/210；只有七维全2且N15完成预审、脱敏、内容正确并经接收者同意的分享，才加4分。最终分将原始0–100分线性映射到整数50–100：原始0→50，原始100→100，按四舍五入取整数。权重为待试玩调整的设计参数，不是经验证的风险模型。

引擎以七维等级和有效分享条件计算最终整数分，不使用浮点数或显示小数：

```python
_SCORE_WEIGHTS = {
    "funds": 21,
    "authorization": 19,
    "privacy": 17,
    "stop_contact": 15,
    "official_help": 13,
    "source_verification": 11,
    "evidence": 9,
}


def calculate_final_score(dimensions, share_bonus_eligible=False):
    """按七维等级返回 50–100 的最终整数分。"""
    if not isinstance(dimensions, dict):
        raise TypeError("dimensions 必须是维度到等级的字典")
    if set(dimensions) != set(_SCORE_WEIGHTS):
        raise ValueError("dimensions 必须且只能包含规定的七个维度")
    if not isinstance(share_bonus_eligible, bool):
        raise TypeError("share_bonus_eligible 必须是布尔值")

    for name, level in dimensions.items():
        if type(level) is not int or level not in (0, 1, 2):
            raise ValueError("{} 的等级必须是整数 0、1 或 2".format(name))

    weighted_total = sum(
        _SCORE_WEIGHTS[name] * dimensions[name]
        for name in _SCORE_WEIGHTS
    )
    if share_bonus_eligible and weighted_total != 210:
        raise ValueError("七个维度全为 2 时才能加分享分")

    # 将原始分 96 * weighted_total / 210 + 4 * bonus
    # 映射到 50–100，并以整数运算执行四舍五入。
    return 50 + (16 * weighted_total + 35) // 70 + (
        2 if share_bonus_eligible else 0
    )
```

share_bonus_eligible=True 只能在七维全2、N15选择分享且分享内容通过预审脱敏并经接收者同意时传入。全0映射为50；全2但不分享映射为98；全2并满足分享条件映射为100。

**路由：** 七项全2时，N15个人闭环进入P01，安全分享进入P02；否则选最低等级的缺口，同级按资金→授权→信息→中止→求助→来源→证据取主要缺口。0进重遗憾，1进轻遗憾。复盘同时展示其余缺口，不让低等级风险被高分抵消。

## 五、徽章与开放题规则

| 徽章 | 触发 |
|---|---|
| 独立核验 | N04完整查询，N11对应结果到达 |
| 权限守门人 | N06未授权，包括此前断联使请求被拦截 |
| 及时刹车 | N08明确结束原可疑会话 |
| 重新掌舵 | 曾有模拟暴露，N09～N11至少完成一项对应补救 |
| 线索保管员 | N13整理必要脱敏经过 |
| 温柔而坚定 | N14用清楚、尊重的方式接受、暂缓或拒绝；三种预设均可 |
| 安全传递者 | N15分享预审、脱敏、正确且对方愿意接收的清单 |

徽章肯定做过的行动，不抵消历史风险。不设置“最会恋爱”“敢相信就奖励”的徽章。

开放题N12/N13/N14采用相同流程：玩家输入→模型提取意图及原文证据→不确定时请玩家选择确认→提交本步固定选项ID→代码记状态。输入“我把所有问题解决了”不能代替执行资金、权限或资料补救。玩家填写真实账号等信息时应请其删除，不将其当作游戏必要输入。
