# 技术栈与 Agent 架构

> 一句话定位：**不是一个“会聊天”的 LLM 套壳，而是一个可审计、可复现、可离线运行的“确定性剧情 Agent”。**
> 它把 Agent 的 `观察 → 决策 → 行动 → 记忆 → 复盘` 闭环，落在反诈训练这个**不能胡说**的场景里。

---

## 1. 为什么这是 Agent 赛道

很多 Agent 作品把“大模型 + 工具调用”当作唯一形态。本项目选择另一条同样成立、但更适合反诈训练的路线：

| 常见 LLM Agent | 本项目：确定性剧情 Agent |
|---|---|
| 模型生成下一步 | 图策略决定下一步 |
| 自由文本可能漂移 | 同一路径必得同一结局/分数 |
| 依赖 API、网络、额度 | 零依赖、断网可跑、零 API 成本 |
| 结果难复算 | 130 条终止路径可逐条复算 |
| 黑箱 | 路径、付款、罚分、徽章全部可解释 |

反诈训练的目标不是“聊得像”，而是**让玩家在压力下做对一次**。因此：
**可解释、可复现、可验收，比“生成得像”更重要。**

## 2. Agent 闭环映射

| Agent 环节 | 本项目实现 | 代码/配置 |
|---|---|---|
| 观察 Observation | 玩家选择、自由回答、当前节点、已发生事件 | `story_frontend_graph.json`、`/api/story/*` |
| 决策 Policy | 图条件路由 + 自由回答关键词意图路由 + 节点校验 | `engine.py`、`static-engine.js` |
| 行动 Action | 节点跳转、付款模拟、提前结局、结局触发 | `engine.py`、图配置 |
| 记忆 Memory | 会话 flags、历史选择、累计付款、TTL | 内存 session store |
| 复盘 Reflection | 路径复盘、整数分数、徽章、结局解释 | `scoring.py`、`build_frontend_review` |
| 工具边界 Tools | `start / answer / open / review` 四个显式 API | `/api/story/*` |
| 护栏 Guardrails | 服务端权威、确定性、无 LLM、无外网、参数校验 | `app.py`、`engine.py` |

> 这里的“工具边界”不是宣传成 LLM function calling，而是**明确的 API 契约**：前端只提交意图，服务端是唯一权威。它具备 Agent 系统最重要的工程属性：**状态、策略、工具、记忆、护栏、可观测复盘**。

## 4. 技术栈分层

| 层 | 选型 | 关键能力 |
|---|---|---|
| 运行时 | Python 3.7+ 标准库 `http.server` | 单进程同时托管 API + 静态页面；零第三方依赖；一条命令启动 |
| 剧情策略 | JSON 图配置 + 确定性路由 | 15 节点、16 结局、条件边、提前结局、flags 状态；无死路 |
| 自由回答 | 关键词意图路由 | N03 核实/继续、N15 删除/分享/举报/官方核实；不依赖 LLM |
| 会话记忆 | 内存 session store | flags / history / paid / TTL 2h；重复提交保护；不落盘 |
| 评分 | 整数评分函数 | 付款每满 100 扣 1、最多扣 50；结局罚分；优秀结局保底 82；10–100 |
| 前端 | 原生 HTML / CSS / JavaScript | 零构建；15 张 AI 场景/立绘；虚拟手机；选项/自由回答；复盘页 |
| 前端引擎 | `static-engine.js` 同构实现 | 与 Python 版同一份图配置/整数规则；GitHub Pages 可独立运行 |
| 音效/动效 | 原生 Web Audio + CSS | 原创 32 秒 BGM、点击/来电/付款/结局音效、转场/打字机/手机抖动 |
| 校验/测试 | `unittest` + 配置校验脚本 | 13 项评分单测；16/16 结局；130 条终止路径全量对拍 |
| 交付 | 本地单进程 / GitHub Pages / Docker | 现场断网可跑；Pages 稳定 Demo；Render/Docker 备用 |

## 5. 项目能力（可写进 PPT 的“硬指标”）

- **剧情规模**：15 个节点、16 个结局（E01–E16）、130 条终止路径；包含提前结局与条件结局。
- **分支质量**：E15/E16 依赖前置核实与付款事件；N04 的“已核实”才进入 N07；N14 的尾款把 E10/E16 分开。
- **评分可复算**：整数评分，无浮点误差；前端静态引擎与后端 Python 的 `ending/score/paid` 多重集一致。
- **工程护栏**：节点 ID 校验、重复提交保护、会话 TTL、CORS、配置校验、异常提示。
- **前端完成度**：15 张 AI 美术、角色立绘、场景切换、虚拟手机、自由回答、结局复盘、徽章、BGM/音效、响应式布局。
- **可交付性**：零依赖启动、断网可演示、GitHub Pages 在线 Demo、Docker/Render 备用部署。

## 6. 30 秒口播（答辩可直接用）

> 我们不是用大模型陪聊，而是把反诈训练做成一个**可审计的剧情 Agent**：
> 玩家每一次选择和回答是 observation，剧情图和关键词路由器做 policy，服务端推进节点、模拟付款、复算分数是 action，会话里的 flags 和已付款金额是 memory，最后给出路径复盘是 reflection。
> 它零依赖、断网可跑，同一路径必得同一结果；130 条终止路径、16 个结局全部验证。
> 对反诈这种不能胡说的场景，**确定性就是能力**。

## 7. PPT 两页文案（可直接贴）

### 第 10 页：技术架构

**标题**：一个可审计的剧情 Agent

**页面要点**
- 观察：选择/自由回答 → 决策：图策略 + 关键词路由 → 行动：节点/付款/结局 → 记忆：会话 flags → 复盘：路径解释
- 工具边界：`/api/story/*` 四个显式 API，服务端唯一权威
- 零依赖：Python 标准库 + 原生前端；断网可跑
- 同构：Python 与 JS 共用同一份图配置和整数评分规则

**口播**：
> 浏览器只提交意图，服务端负责状态、策略和评分；它不是黑箱，每一步都能复盘。

### 第 11 页：为什么是 Agent 赛道

**标题**：反诈训练，不需要“会胡说”的 Agent

**页面要点**
- 不是 LLM 套壳：不生成下一步，而是用可验证的图策略推进
- 可复现：同一条路径，结局和分数永远一致
- 可验收：130 条终止路径、16 个结局、13 项单测全部可复算
- 可扩展：自由回答现在用关键词路由，可在路由层替换为 LLM 意图分类；当前版本保持零依赖/断网可跑

**口播**：
> 大多数 Agent 在比“生成得像”，我们在比“敢不敢让评委复算”。反诈场景，确定性就是能力。

## 8. 边界与下一步

- **当前不做**：不调用大模型、不接外部 API、不采集用户输入、不接真实支付。
- **当前取舍**：自由回答用关键词路由，覆盖 N03/N15 的关键动作；不假装成“通用语义理解”。
- **下一步**：在不破坏确定性兜底的前提下，增加 LLM 意图分类/自由回答评分；增加语音输入；增加教师/社区后台。
- **披露**：在线 GitHub Pages 版本是**前端同构实现**；Python 后端版本在仓库 `backend/`，可本地运行。
