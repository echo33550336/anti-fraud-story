# 前后端接口对齐

## 1. 当前前端接入点

`src/game.js` 检查 `window.evaluateFreeAnswer`。存在该函数时，提交 N03 / N15 自由回答会调用：

```js
await window.evaluateFreeAnswer({
  node_id: "N03", // 或 "N15"
  text: "我会自己找剧院电话核实，并保存聊天记录",
  history: [{ node: 1, answer: "查看票面：记住演出时间、座位和票号" }],
  state: {
    ticketPaid: 0,
    secondPaid: 0,
    smallPaid: 0,
    investPaid: 0,
    verifiedOfficial: false,
    stopped: false
  }
});
```

当前前端只读取返回值的 `target` 或 `ending_id`，例如：

```json
{"target":"E01"}
```

允许目标：N03 → `E01` 或 `4`；N15 → `E11`、`E12`、`E13`、`E14`。N03 若返回数字 `4`，会继续第 4 节点；返回 `E01` 则结束。返回空值时前端提示用户补充行动，不推进。**N03 早期结束时不会出现 N15。**

## 2. 当前结算接入点

前端进入结局后写入 `window.lastGameResult`，并派发 `document` 的 `game:ended` 事件，事件 `detail` 即为这个对象：

```json
{
  "ending_id": "E12",
  "score": 82,
  "history": [{"node":1,"answer":"查看票面：记住演出时间、座位和票号"}],
  "state": {
    "ticketPaid":0,"secondPaid":0,"smallPaid":0,"investPaid":0,
    "verifiedOfficial":false,"stopped":true
  }
}
```

其中 `score` 是本地演示值，后端不可把它当作权威输入。后端可返回：

```js
window.setGameResult({
  ending_id: "E12",
  score: 91,
  badges: ["独立核验", "及时刹车", "线索保管员"]
});
```

页面仅在后端 `ending_id` 与已显示结局相同时更新分数、徽章，并显示“后端评分”。目前页面没有自动向服务器发起结算请求；对接方需监听 `game:ended` 并添加请求逻辑。`setGameResult` 不展示后端复盘字段，也不支持改写已落定的结局。

## 3. 建议后端协议

由服务端维护 `session_id` 和权威状态。固定选项提交 `{session_id,node_id,option_id}`；自由回答提交 `{session_id,node_id,text}`。响应统一返回 `{next_node_id,ending_id,feedback,state}`，其中下一节点和结局二选一。结局另返回 `{ending_id,score,badges,review}`。前端所传 `history/state` 可供展示与调试，但服务端应按已记录事件复算，避免客户端改写支付、核验等事实。

## 4. 对接前必须统一的剧情规则

1. 旧后端配置是两张票、N12–N14 开放题；本页面是一张票、N03/N15 开放题。需要新建或替换后端剧情配置。
2. 本页面的 `freeRoute`、`scoreFor`、`badgesFor` 是离线演示逻辑，不是 Agent 评分器。对接后应明确后端为权威。
3. 当前前端按所选按钮进入结局，后端只可覆盖同一结局的分数和徽章。若要由后端决定结局，需要把固定选项提交和结局跳转也改为等待后端响应。
4. `history` 目前记录节点编号和选项文字，没有稳定的 `option_id`。正式接口应增加选项 ID，避免文案修改影响评分。
5. 结局 E14 在当前路径上可能已发生模拟付款。若“完美结局”要求零损失，须先统一剧情可达条件和判分标准。
